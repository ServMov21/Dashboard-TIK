## 1. Fitur Baru

### 1.1 Recently Deleted (Trash & Recovery) — Baru
Sebelumnya, saat guru menghapus hasil tugas siswa (file maupun mengetik), data langsung hilang permanen dan file fisiknya ikut dihapus dari server. Sekarang:

- Setiap penghapusan **disnapshot dulu** ke tabel `SampahPengumpulan` sebelum record aslinya dihapus.
- **File fisik TIDAK langsung dihapus** — baru benar-benar dihapus saat guru melakukan "Hapus Permanen" dari halaman Recently Deleted.
- Guru mendapat menu baru **"Recently Deleted"** di sidebar (ikon tempat sampah), berisi daftar semua hasil tugas yang pernah dihapus (file & mengetik), lengkap dengan nama siswa, judul tugas, waktu dihapus, dan nilai/skor terakhir.
- Dua aksi tersedia per baris:
  - **Restore** — mengembalikan data ke tabel asli (`Pengumpulan` / `PengumpulanMengetik`). Ditolak otomatis jika siswa yang bersangkutan sudah mengumpulkan ulang tugas tersebut (mencegah data baru tertimpa data lama).
  - **Hapus Permanen** — menghapus snapshot + file fisik dari server, tidak bisa dipulihkan lagi (ada dialog konfirmasi).
- Siswa yang mengumpulkan ulang tugas yang datanya sedang berada di trash **tetap bisa mengumpulkan seperti biasa** (tidak terblokir oleh data lama di trash).

### 1.2 Riwayat XP — Dirinci Per Komponen
Sebelumnya satu baris riwayat menumpuk semua komponen jadi satu angka (misal `+250 XP`). Sekarang setiap komponen XP tampil sebagai baris terpisah dengan keterangan jelas:

| Komponen | Contoh Tampilan |
|---|---|
| XP dasar menyelesaikan tugas | "Menyelesaikan TUGAS MENGETIK CERITA" → **+80 XP** |
| Bonus dari nilai | "Mendapat BONUS NILAI 90 dari TUGAS MENGETIK CERITA" → **+80 XP** |
| Early submission | "Mendapat Early Submission dari TUGAS MENGETIK CERITA" → **+90 XP** |
| Nilai sempurna (100) | "Mendapat Nilai Sempurna (100) dari TUGAS MENGETIK CERITA" → **+70 XP** |
| Bonus tambahan dari guru | "Mendapat Bonus Tambahan dari Guru untuk TUGAS MENGETIK CERITA" → **+20 XP** |
| Penalti tidak mengumpulkan | "Tidak mengumpulkan/mengerjakan TUGAS ..." → **−XP** |

Baris hanya muncul kalau komponen tersebut memang bernilai (>0), jadi tidak ada baris kosong.

### 1.3 Acak Tempat Duduk — Proporsi Berdampingan & Tag "Tidak Masuk"
- **Tag baru "Tidak Masuk"**: siswa yang absen bisa ditandai terpisah dari tag "Wajib Berdampingan", dan otomatis dikeluarkan sepenuhnya dari proses acak (tidak dapat tempat duduk, tidak ikut dihitung kapasitas).
- **Aturan pasangan wajib diperbaiki**: siswa yang ditandai *wajib berdampingan* sekarang **selalu dipasangkan dengan teman acak yang TIDAK ditandai** — bukan dipasangkan sesama siswa yang ditandai seperti sebelumnya.
- **Proporsi pasangan berdasarkan jumlah gender** (fitur baru sesuai permintaan): jumlah siswa yang duduk berdampingan (2 per komputer) dihitung proporsional terhadap total siswa per gender, dikalibrasi dari 2 contoh acuan:
  - 16 siswa (gender sama) → minimal **5 pasang** berdampingan
  - 5 siswa (gender sama) → maksimal **2 pasang** berdampingan
  - Formula: `pasangan = round(jumlah × 0.3125)`, dibatasi maksimal 2 pasang untuk grup ≤6 orang, dan tidak pernah melebihi kapasitas fisik (`floor(jumlah/2)`).
  - Kalau kapasitas 16 komputer memaksa lebih banyak pasangan (total siswa aktif > 16), sistem otomatis menaikkan jumlah pasangan secukupnya supaya **16 komputer selalu terisi penuh** (selama total siswa aktif ≤ 32).
- Ringkasan hasil acak ditampilkan di atas layout ruangan: total siswa aktif, jumlah laki-laki/perempuan beserta jumlah pasangannya, dan jumlah pasangan wajib (tag).
- Daftar siswa yang "Tidak Masuk" ditampilkan terpisah di bawah layout ruangan setelah acak selesai.

### 1.4 Preview File Tanpa Download (Popup)
- Dibuat komponen preview terpusat (`FilePreviewModal`) dan dipasang di semua tempat yang sebelumnya hanya punya tombol **Download**:
  - Halaman **Pengumpulan Tugas** (guru)
  - Halaman **Detail Tugas** (lampiran tugas, hasil kerja siswa per-siswa, dan file milik siswa sendiri)
  - Halaman **Rekap Nilai Siswa** (preview hasil kerja sendiri)
- Popup mendukung: gambar (langsung tampil), PDF (iframe), dan file lain (tombol buka/download).

### 1.5 Preview DOCX & XLSX di Browser (Tanpa Download)
Sebelumnya file `.docx`/`.xlsx` tidak bisa dipratinjau — otomatis ke-download. Sekarang:
- Server mengonversi `.docx`/`.doc` → HTML (pakai library **mammoth**) dan `.xlsx`/`.xls` → tabel HTML (pakai library **xlsx** yang sudah dipakai untuk fitur export), lalu dikirim ke popup preview sebagai fragment HTML aman.
- Endpoint baru: `GET /api/pengumpulan/preview-html/:id` dan `GET /api/tugas/lampiran/:id/preview-html`.
- Kalau konversi gagal (misal file rusak), popup otomatis menampilkan tombol "Download Saja" sebagai fallback.

### 1.6 Riwayat Tugas (Akun Siswa) — Dihapus
Menu **"Riwayat Tugas"** di sidebar siswa dan halamannya dihapus karena datanya sudah terwakili sepenuhnya oleh **Rekap Nilai**.

## 3. Panduan Migrasi Database

Migrasi baru (`add_sampah_pengumpulan`) sudah disertakan di folder `server/prisma/migrations/`. Karena `start.bat` sudah otomatis menjalankan `npx prisma migrate deploy` setiap kali start, **tidak perlu langkah manual tambahan** — cukup jalankan seperti biasa:

```bat
cd "D:\Dashboard-TIK"
start.bat
```

Jika ingin menjalankan migrasi manual:

```bat
cd server
npx prisma generate
npx prisma migrate deploy
```

## 4. Catatan Pengujian

- Konversi DOCX → HTML (mammoth) dan XLSX → HTML (xlsx) sudah diuji langsung dengan file sample dan berhasil menghasilkan output yang benar.
- Algoritma acak tempat duduk sudah divalidasi secara matematis: total device yang terpakai selalu ≤ 16 selama total siswa aktif ≤ 32, dan rasio pasangan mengikuti formula `round(jumlah × 0.3125)` sesuai 2 contoh acuan dari pengguna.
- Server tidak bisa dijalankan langsung di lingkungan pengecekan (engine Prisma yang di-bundle khusus Windows), sehingga pengujian penuh (end-to-end) perlu dilakukan di mesin Windows tempat aplikasi biasa dijalankan. Semua file sudah divalidasi sintaksnya (Node.js `--check` untuk server, parser Babel/JSX untuk client).
